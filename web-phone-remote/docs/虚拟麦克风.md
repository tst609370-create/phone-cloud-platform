# 电脑麦克风注入手机

控制端在投屏工具栏点麦克风，用电脑麦克风作为被控安卓手机的麦克风输入。微信「按住说话」和微信语音通话走的是应用自己的 `AudioRecord`，所以必须把 PCM 送进这条录音通路，而不是只在手机外放。

投屏、快照模式、租用鉴权都不走这条新通道。麦克风 WebSocket 的 action 是 `mic`，和非管理员的 `stream` / `probe` 一样，必须通过现有登录态，并且 `deviceAccess` 判定这台设备分配给了当前用户。

## 怎么用

1. 打开实时投屏（不是快照墙）。工具栏里多一个麦克风按钮。
2. 按钮先显示「正在检测麦克风…」。检测完如果这台手机不能注入，按钮置灰，悬停文字是原因。
3. **按住按钮说话**：按住超过约 0.3 秒开始推流，松开停止。适合微信按住说话。请先按住电脑上的按钮，再按手机里的「按住说话」，这样录音开始时注入已经开着。
4. **单击按钮**：切换持续注入，按钮变绿。适合语音通话。再单击关闭。通话前先单击打开，再在微信里拨打。
5. 浏览器会向本页申请麦克风。页面必须是 localhost 或 HTTPS。拒绝授权时按钮旁的提示会写成浏览器错误。

关闭投屏窗口会关掉注入。shell 路径注册过的音频策略随注入进程退出而释放；LSPosed 路径在关闭后钩子重新走手机原来的麦克风。

## 服务端怎么选路

探测结果写在设备 probe 的 `mic` 字段里，真正开麦时还会再确认一次。顺序是：

| 条件 | 通道 |
| --- | --- |
| 已安装包名 `com.wsphone.virtualmic` 的 LSPosed 模块 | 优先。钩子替换 MIC / 语音识别 / 语音通话等 `AudioRecord`。失败再试 shell |
| 未装模块，Android 13+（API 33），且服务端带有 `virtual-mic.jar` | shell 以 `com.android.shell` 注册 AudioPolicy loopback，把 PCM 写进匹配的录音预设 |
| 会话中当前通道写失败 | 自动换下一条，并把原因写回按钮 |
| 两条都不行 | 按钮置灰，原因包含 root、模块、API 级别或 shell 注册失败 |

shell 通道在第一次按下时才会真正 `registerAudioPolicy`。平时打开投屏不会抢占手机麦克风。

## 支持范围

- **已 root，并在 LSPosed 里启用本模块、作用域包含微信**：这是微信语音能稳定听到电脑麦的路径。模块源码、Magisk 包装和安装步骤在 [`android/virtual-mic/README.md`](../android/virtual-mic/README.md)。
- **未 root，Android 13 及以上**：服务端会推送 shell 注入组件并尝试注册 AudioPolicy。AOSP 的 shell 往往有 `MODIFY_AUDIO_ROUTING`，不少零售固件没有。注册失败时按钮置灰，提示 shell 音频策略注册失败。
- **未 root 且低于 Android 13**：没有可尝试的通道，按钮置灰。
- **快照模式**：不提供这个按钮，抽帧和触控保持原样。

## 已知限制

- 微信按住说话、语音通话都在微信进程里读麦克风。没装钩子、又没能注册 AudioPolicy 时，系统不提供「把任意 PCM 变成别的应用的麦克风」的公开接口，按钮只能置灰。
- shell 注入必须在目标应用**打开录音之前**注册好。已经按住微信再去按电脑按钮，这一句可能仍走手机麦；松开重按即可。LSPosed 钩子是每次 `read` 都判断的，晚按电脑按钮也会切过来。
- 钩子故意不处理 `REMOTE_SUBMIX`（音频源 8）。那是 scrcpy 采集手机播放声音用的，替换它会破坏投屏里的手机声音。
- 部分机型的微信通话不走 `AudioRecord`，而走通话 HAL。这种通话 shell 和钩子都喂不进去。
- 同一台手机同时只服务一个控制端。第二个麦克风连接不会抢占，按钮会提示正被另一个控制端使用。
- `adb reverse` 被 SELinux 拦住时，LSPosed 通道会失败并尝试 shell。
- 注入的是 48 kHz 单声道 s16le，微信常用 16 kHz，桥接会重采样。音质够语音，不是音乐级。
- 按住说话松开后：LSPosed 会交回真实麦克风；shell 在本次投屏的注入会话里仍占着录音预设，不说话时对方听到的是静音，直到关闭投屏或关掉持续注入并结束会话（关闭投屏窗口会拆掉策略）。

## 协议

浏览器到 Node 仍是原来的 WebSocket（带登录 cookie）：

- 文本 `{ "type": "start", "mode": "ptt" | "continuous" }`、`{ "type": "stop" }`、`{ "type": "format", "sampleRate": 48000 }`
- 二进制：单声道 s16le
- 服务端回 `{ "type": "status", "supported", "route", "reason", "active", ... }`

手机侧帧格式（1 字节类型 + 4 字节大端长度 + 载荷）在 `src/common/micProtocol.ts`，shell 注入进程和 LSPosed 客户端按同一份实现。

## 构建 shell 组件

服务端在 `android/virtual-mic/prebuilt/virtual-mic.jar`（或环境变量 `WS_VIRTUAL_MIC_JAR`，或打包进 `dist/virtual-mic.jar`）找到注入包才会尝试 shell 通道。重新编译：

```bash
sh android/virtual-mic/build-shell-jar.sh
```

需要 JDK 21（或任何带 `javac --release 8` 的 JDK）和首次下载 d8 的网络。
