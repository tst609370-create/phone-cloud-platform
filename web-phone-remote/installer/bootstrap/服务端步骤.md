# 从当前 503 服务迁到邀请兑付

当前机器上这些不要动：frps、8088、Caddy 已经签发的 `https://103.205.240.23:7443` 证书。Caddy 继续把 7443 反代到 `127.0.0.1:7100`。不要把 FRP 共享令牌写进任何下面的文件。

仓库里的新进程不再读取 `FRP_TOKEN`，也不再认识 `ENROLL_OPEN`。把现在那个对公网 `/v1/register` 固定返回 503 的进程换成下面三个文件，放在同一目录：

- `server.mjs`
- `enroll.mjs`
- `assignPort.mjs`

```bash
sudo mkdir -p /opt/phone-remote /var/lib/phone-remote
sudo cp server.mjs enroll.mjs assignPort.mjs /opt/phone-remote/
sudo cp phone-remote-register.service /etc/systemd/system/phone-remote-register.service
sudo systemctl daemon-reload
sudo systemctl enable --now phone-remote-register.service
sudo systemctl restart phone-remote-register.service
```

换完后的检查（应不再是 503）：

```bash
curl -fsS http://127.0.0.1:7100/healthz
curl -fsS https://103.205.240.23:7443/healthz
curl -sS -o /tmp/reg-body.txt -w '%{http_code}\n' -X POST https://103.205.240.23:7443/v1/register \
  -H 'content-type: application/json' -d '{}'
```

`/healthz` 为 `{"ok":true}`。空注册为 `400`，正文里没有 `token`。若仍是 `503`，说明 7100 上还是旧进程。

个性化安装包在这台机器或另一台运维机器上生成，不要放进公开目录：

```bash
node /opt/phone-remote/personalize.mjs \
  --base /secure/PhoneRemoteSetup.exe \
  --out /secure/PhoneRemote-某用户.exe \
  --store /var/lib/phone-remote/enrollment.json
```

`personalize.mjs` 与 `enroll.mjs`、`assignPort.mjs` 放在一起。标准输出只有 `inviteId` 和输出路径。

frps 端口插件不是这次替换 7100 的必要步骤。要启用时，只把 `frps-plugin.toml` 里的 `[[httpPlugins]]` 追加到现有 frps 配置，不要改已有令牌行，不要动 8088，然后只重载 frps。插件不能代替共享令牌校验；本服务不持有该令牌。没有插件时，持有共享令牌的客户端仍可在 10000–10100 自行选端口。

# 注册与端口授权

公共 exe 不含邀请，也不含 FRP 共享令牌。小白不用输入，也不用放配置文件。只有运维私下交出的个性化 exe 会在安装时自动访问：

`https://103.205.240.23:7443/v1/register`

## 兑付

请求：

```json
{"deviceId":"<32位hex>","invite":"<64位hex，只存在于私有exe>"}
```

邀请是 32 字节随机值，服务器只存 SHA-256。兑付是一次性的：成功后状态变为已使用，同时分配 10000–10100 中的一个空闲端口，返回只出现一次的 `deviceSecret`。响应里没有 `token`。请求仍然只需要 `deviceId` 和 `invite`，与已经发出的 v2 安装包相同。客户端不能在请求里自行指定恢复目标。

普通邀请的 `targetDeviceId` 为空，只能登记一台还没有记录的设备。已经存在的设备要换密钥，必须先由运维把这份未使用邀请的 `targetDeviceId` 写成那台设备的 ID。兑付时设备 ID 必须一致，端口保持第一条记录上的端口，旧密钥失效。邀请不会因为一次失败的兑付就被消耗。

被 `revokeDevice` 撤销的设备，即使恢复邀请已经写明它的 ID，兑付也不会把 `revoked` 改回。要先单独执行 `--authorize-device`。这一步只恢复原来的密钥，不打印邀请，也不生成新密钥。

同一个 `deviceId` 如果有多条记录，只保留第一条的端口、密钥和撤销状态。后面追加的密钥一律丢弃，避免把攻击者后写入的密钥当成有效密钥。

这次替换 `/opt/phone-remote/server.mjs`、`/opt/phone-remote/enroll.mjs` 和用于管理命令的 `/opt/phone-remote/personalize.mjs`，然后重启 7100。`assignPort.mjs` 不用换。重启前复制一份 `/var/lib/phone-remote/enrollment.json`。不要手改重复行，也不要把 `secretHash` 或邀请原文写进日志。不要动 frps、8088 和 Caddy。已发出的安装包不用换。

绑定朋友已经拿到的那份未使用邀请（把两个 ID 换成实际值，命令里不要出现邀请原文）：

```bash
node /opt/phone-remote/personalize.mjs \
  --store /var/lib/phone-remote/enrollment.json \
  --bind-invite <INVITE_ID> \
  --target-device <DEVICE_ID>
```

标准输出只有 `inviteId` 和 `targetDeviceId`。朋友重跑原来的私有 exe 时，请求体仍是 `deviceId` 和 `invite`。若那台电脑已经有 `device-auth.json`，v2 会继续用里面的密钥调用 `/v1/config`，不会再次兑付。

撤销未使用的邀请后，兑付返回 403。同一邀请不能绑到第二台设备。之后的 `POST /v1/config` 必须同时带 `deviceId` 和 `deviceSecret`；只知道 deviceId 不行。撤销设备后，旧密钥也失效。端口号仍然占着，不会立刻发给别人。

个性化打包（在服务器或运维机器上，不要把产物放进公开目录）：

```bash
node personalize.mjs --base PhoneRemoteSetup.exe --out /secure/PhoneRemote-某用户.exe --store /var/lib/phone-remote/enrollment.json
node personalize.mjs --base PhoneRemoteSetup.exe --out /secure/PhoneRemote-恢复.exe --store /var/lib/phone-remote/enrollment.json --target-device <DEVICE_ID>
node personalize.mjs --store /var/lib/phone-remote/enrollment.json --authorize-device <DEVICE_ID>
```

标准输出只有 `inviteId`、输出路径或设备 ID。密钥不打印。要作废未使用的邀请，把对应记录的 `status` 改成 `revoked`（或调用 `revokeInvite`）。已兑付的邀请改不回去。撤销设备用 `revokeDevice`；恢复撤销状态只能用 `--authorize-device`。

## 你已经交给运维的接入

- 公网 HTTPS：`103.205.240.23:7443`
- 注册服务：`127.0.0.1:7100`
- 证书必须被 Windows 信任，并且包含 IP `103.205.240.23`
- 客户端不跳过证书校验，也不接受跳到明文 HTTP
- 参考文件：`phone-remote-register.service`、`Caddyfile.example`
- 这两个文件和仓库里都没有 FRP 共享令牌。不要把令牌写进来。

## frps 每设备端口插件的边界

参考片段：`frps-plugin.toml`。把它加到现有 frps 配置旁，指向 `127.0.0.1:7100/frp/handler`，操作是 `Login` 和 `NewProxy`。

插件能做的：在 frps 已经接受这条连接之后，核对 `user` 和 `metadatas.deviceSecret`，并拒绝不是该设备端口的 `NewProxy`。没有设备密钥、密钥已撤销、或端口不对，都会被拒绝。

插件不能做的：

- 它不能代替 frps 自己的共享令牌校验。令牌不对时，请求到不了插件。
- 本安装器不索取、不内置、不回传这个共享令牌。因此私有 exe 写好的 `frpc.toml` 没有 `auth.token`。在 frps 仍要求共享令牌时，隧道不会因为这次安装就连上。
- 谁手里已经有共享令牌，谁就有较大权限：没有挂上这个插件时，对方可以在 10000–10100 里自己选端口。挂上插件后，没有匹配设备密钥的连接开不了代理，但仍然可以尝试登录并消耗连接。插件不能收回已经泄漏的共享令牌。

所以：邀请兑付是安装身份；插件是端口边界；共享令牌仍是 frps 的门。三者不要混成“拿到 deviceId 就能用全局令牌”。

## 麦克风

公网 `http://103.205.240.23:端口` 不能开麦。本机 `http://127.0.0.1` 可以。远程开麦需要另一张受信任证书。没有真机测试，不能把麦克风或隧道说成已经可用。
