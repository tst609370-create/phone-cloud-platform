# 注册与端口授权

公共 exe 不含邀请，也不含 FRP 共享令牌。小白不用输入，也不用放配置文件。只有运维私下交出的个性化 exe 会在安装时自动访问：

`https://103.205.240.23:7443/v1/register`

## 兑付

请求：

```json
{"deviceId":"<32位hex>","invite":"<64位hex，只存在于私有exe>"}
```

邀请是 32 字节随机值，服务器只存 SHA-256。兑付是一次性的：成功后状态变为已使用并绑定这个 deviceId，同时分配 10000–10100 中的一个空闲端口，返回只出现一次的 `deviceSecret`。响应里没有 `token`。

撤销未使用的邀请后，兑付返回 403。同一邀请不能绑到第二台设备。之后的 `POST /v1/config` 必须同时带 `deviceId` 和 `deviceSecret`；只知道 deviceId 不行。撤销设备后，旧密钥也失效。端口号仍然占着，不会立刻发给别人。

个性化打包（在服务器或运维机器上，不要把产物放进公开目录）：

```bash
node personalize.mjs --base PhoneRemoteSetup.exe --out /secure/PhoneRemote-某用户.exe --store /var/lib/phone-remote/enrollment.json
```

标准输出只有 `inviteId` 和输出路径。密钥不打印。要作废未使用的邀请，把对应记录的 `status` 改成 `revoked`（或调用 `revokeInvite`）。已兑付的邀请改不回去，应 `revokeDevice`。

## 你已经交给运维的接入

- 公网 HTTPS：`103.205.240.23:7443`
- 注册服务：`127.0.0.1:7100`
- 证书必须被 Windows 信任，并且包含 IP `103.205.240.23`
- 客户端不跳过证书校验，也不接受跳到明文 HTTP
- 参考文件：`phone-remote-register.service`、`Caddyfile.example`
- 这两个文件和仓库里都没有 FRP 共享令牌。不要把令牌写进来。

## frps 每设备端口插件的边界

参考片段：`frps-plugin.toml`。把它加到现有 frps 配置旁，指向 `127.0.0.1:7100/frp/handler`，操作是 `Login` 和 `NewProxy`。

插件能做的：在 frps 已经接受这条连接之后，核对 `user` 和 `metadatas.deviceSecret`，并拒绝不是该设备端口的 `NewProxy`。没有设备密钥、密钥已撤销、或端口不对，都会被拒绝。

插件不能做的：

- 它不能代替 frps 自己的共享令牌校验。令牌不对时，请求到不了插件。
- 本安装器不索取、不内置、不回传这个共享令牌。因此私有 exe 写好的 `frpc.toml` 没有 `auth.token`。在 frps 仍要求共享令牌时，隧道不会因为这次安装就连上。
- 谁手里已经有共享令牌，谁就有较大权限：没有挂上这个插件时，对方可以在 10000–10100 里自己选端口。挂上插件后，没有匹配设备密钥的连接开不了代理，但仍然可以尝试登录并消耗连接。插件不能收回已经泄漏的共享令牌。

所以：邀请兑付是安装身份；插件是端口边界；共享令牌仍是 frps 的门。三者不要混成“拿到 deviceId 就能用全局令牌”。

## 麦克风

公网 `http://103.205.240.23:端口` 不能开麦。本机 `http://127.0.0.1` 可以。远程开麦需要另一张受信任证书。没有真机测试，不能把麦克风或隧道说成已经可用。
